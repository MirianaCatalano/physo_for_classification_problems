# Pipeline

The analysis pipeline is organized into a sequence of steps, from synthetic dataset generation to result visualization.

```
01_generate_dataset.py
        ↓
02_binarize_label.py
        ↓
03_split_dataset.py
        ↓
04_run_physo.py
        ↓
05A_evaluate_best_expression.py / 05B_evaluate_pareto_front.py
        ↓
06_results_summary.py
        ↓
07A_plot_histograms.py / 07B_plot_heatmaps.py
```

## 1. Dataset Generation

### `01_generate_dataset.py`

**Purpose**

The script generates a synthetic dataset from a selected Feynman equation using the `FeynmanProblem` class provided by PhySO.

For each selected equation, both the original noiseless target and a noisy version of the target are generated and stored.

**Configuration**

The script reads its parameters from:

```
configs/01_generate_dataset_config.json
```

The main parameters are:

* `N_SAMPLES`: number of samples to generate.
* `NOISE_LEVEL`: relative level of Gaussian noise added to the target.
* `SEED`: random seed used for reproducibility.
* `UNIT_NAMES`: names of the physical units used to construct the unit table.
* `EQ_TO_TEST`: equation index and name identifying the Feynman equation.
* `EXPERIMENT_NAME`: name assigned to the experiment.

The configuration parameters are validated before being used.

**Input**

The script requires:

* the configuration file `01_generate_dataset_config.json`;
* the selected Feynman equation available through PhySO's `FeynmanProblem`.

No input dataset is required, since the dataset is generated from scratch.

**Processing**

The script performs the following operations:

1. Loads and validates the configuration parameters.
2. Sets the NumPy, Python `random`, and PyTorch random seeds.
3. Creates the experiment directory under `tests/`.
4. Initializes the selected Feynman equation through `FeynmanProblem`.
5. Generates `N_SAMPLES` input samples and their corresponding noiseless target values.
6. Computes the root-mean-square value of the target.
7. Adds Gaussian noise to the target according to the configured `NOISE_LEVEL`.
8. Creates a pandas DataFrame containing the input variables and the two target variables:

   * `y`: noiseless regression target;
   * `y_noisy`: noisy regression target.
9. Builds a table containing the physical units associated with the input variables and target.
10. Saves metadata describing the generated dataset.

**Output**

The generated files are stored in:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── generated_dataset/
```

The following files are produced:

```
generated_dataset/
├── dataset.csv
├── unit_table.csv
└── dataset_config.json
```

* **`dataset.csv`** contains the generated input variables, the noiseless target `y`, and the noisy target `y_noisy`.
* **`unit_table.csv`** contains the physical-unit exponents associated with each input variable and target.
* **`dataset_config.json`** stores metadata about the generated dataset, including the equation, number of samples, noise level, seed, target RMS, input ranges, and generation parameters.

The generated dataset is used by `02_binarize_label.py`, which converts the continuous target into binary classification labels for the classification experiments.

## 2. Label Binarization

### `02_binarize_label.py`

**Purpose**

The script converts the continuous regression targets generated in the previous step into binary classification labels.

For each configured quantile threshold, a binary label is generated for both the noiseless target `y` and the noisy target `y_noisy`.

**Configuration**

The script reads its parameters from:

```
configs/02_binarize_label_config.json
```

The main parameters are:

* `EQ_TO_TEST`: identifies the Feynman equation to process.
* `EXPERIMENT_NAME`: identifies the experiment containing the generated dataset.
* `QUANTILE_THRESHOLD`: list of quantiles used to define the classification thresholds.

**Input**

The script uses the files generated by `01_generate_dataset.py`:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── generated_dataset/
            ├── dataset.csv
            └── dataset_config.json
```

The `dataset.csv` file must contain the continuous targets `y` and `y_noisy`.

The `dataset_config.json` file is loaded to preserve and update the metadata associated with the dataset.

**Processing**

For each quantile specified in `QUANTILE_THRESHOLD`, the script:

1. Loads the generated dataset and its configuration.
2. Computes the quantile threshold separately for `y` and `y_noisy`.
3. Creates a binary label for the noiseless target:

   * `y_bin_<quantile>`
4. Creates a binary label for the noisy target:

   * `y_noisy_bin_<quantile>`
5. Assigns label `1` to samples whose target is greater than or equal to the corresponding threshold, and `0` otherwise.
6. Stores the numerical thresholds in the dataset metadata.
7. Updates and saves the dataset and its configuration.

For example, for a quantile of `0.75`, the following columns are created:

```
y_bin_75
y_noisy_bin_75
```

and the corresponding thresholds are stored under:

```
"binarization": {
    "thr_75": {
        "y_threshold": ...,
        "y_noisy_threshold": ...
    }
}
```

If the binary columns for a given quantile already exist, the script skips that quantile to avoid repeating the binarization.

**Output**

The script updates the existing files rather than creating a new directory:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── generated_dataset/
            ├── dataset.csv          # updated with binary labels
            └── dataset_config.json  # updated with binarization metadata
```

The resulting `dataset.csv` contains both the original continuous targets and the binary classification labels.

For the configured thresholds `0.50`, `0.75`, and `0.90`, the dataset can contain:

```
y_bin_50
y_noisy_bin_50
y_bin_75
y_noisy_bin_75
y_bin_90
y_noisy_bin_90
```

The updated dataset is used by `03_split_dataset.py`, which generates the training and test splits for both regression and classification tasks.

## 3. Dataset Splitting

### `03_split_dataset.py`

**Purpose**

The script generates the training and test splits used in the subsequent regression and classification experiments.

The generated splits are stored separately for:

* regression and classification tasks;
* clean and noisy datasets;
* each classification threshold.

**Configuration**

The script reads its parameters from:

```
configs/03_split_dataset_config.json
```

The main parameters are:

* `EQ_TO_TEST`: identifies the Feynman equation to process.
* `EXPERIMENT_NAME`: identifies the experiment containing the binarized dataset.
* `SPLITS_FOLDER_NAME`: name of the directory where the splits are stored.
* `N_FOLDS`: total number of splits to generate.
* `SEED`: random seed used for reproducibility.

The configured number of folds must be a multiple of 5. The script performs repeated 5-fold splitting, with:

```
number of repeats = N_FOLDS / 5
```

For example, with `N_FOLDS = 10`, two independent 5-fold repetitions are performed, resulting in 10 splits.

**Input**

The script uses the dataset generated and updated by the previous pipeline steps:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── generated_dataset/
            └── dataset.csv
```

The dataset must contain:

* the input features;
* the continuous targets `y` and `y_noisy`;
* the binary labels generated by `02_binarize_label.py`.

The columns corresponding to targets and binary labels are excluded from the feature matrix.

**Processing**

The script first extracts the input features from `dataset.csv`.

It then generates two types of splits.

#### Regression

For regression, the script uses `KFold` with:

* 5 folds per repetition;
* shuffling enabled;
* a reproducible random state based on the configured seed.

The same train/test indices are used for both the clean target `y` and the noisy target `y_noisy`, since the K-fold split does not depend on the target values.

The resulting datasets are stored separately as:

```
regression/
├── clean/
└── noisy/
```

#### Classification

For each binary classification threshold found in the dataset, the script creates a separate threshold directory:

```
classification/
├── thr_50/
├── thr_75/
└── thr_90/
```

Within each threshold directory, clean and noisy datasets are further separated:

```
thr_<threshold>/
├── clean/
└── noisy/
```

For classification, the script uses `StratifiedKFold` with:

* 5 folds per repetition;
* shuffling enabled;
* the configured seed;
* stratification based on the corresponding binary labels.

Clean and noisy classification labels are therefore split separately, since the class labels determine the stratification.

**Output**

The splits are stored under:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── <splits_folder_name>/
```

The resulting structure is:

```
<splits_folder_name>/
├── regression/
│   ├── clean/
│   │   ├── X_train_fold0.csv
│   │   ├── X_test_fold0.csv
│   │   ├── y_train_fold0.csv
│   │   ├── y_test_fold0.csv
│   │   └── ...
│   └── noisy/
│       ├── X_train_fold0.csv
│       ├── X_test_fold0.csv
│       ├── y_train_fold0.csv
│       ├── y_test_fold0.csv
│       └── ...
├── classification/
│   ├── thr_50/
│   │   ├── clean/
│   │   └── noisy/
│   ├── thr_75/
│   │   ├── clean/
│   │   └── noisy/
│   └── thr_90/
│       ├── clean/
│       └── noisy/
└── split_config.json
```

Each `clean/` or `noisy/` directory contains four files for each split:

* `X_train_fold<i>.csv`
* `X_test_fold<i>.csv`
* `y_train_fold<i>.csv`
* `y_test_fold<i>.csv`

The script also saves `split_config.json`, which records the main splitting parameters and methods used, including the number of folds, number of repetitions, seed, and whether `KFold` or `StratifiedKFold` was used.

The generated splits are used by `04_run_physo.py`, which runs PhySO independently on the selected task, threshold, data type, and split configuration.

## 4. Symbolic Regression with PhySO

### `04_run_physo.py`

**Purpose**

The script runs the symbolic discovery phase using PhySO on each fold generated by `03_split_dataset.py`.

The task configuration determines whether PhySO is run in a **regression** or **classification** setting, and whether the **clean** or **noisy** dataset is used.

For classification experiments, the selected quantile threshold identifies the corresponding set of binary labels and splits.

A separate PhySO run is performed for each fold.

**Configuration**

The script reads its parameters from:

```
configs/04_run_physo_config.py
```

The configuration contains:

* experiment and dataset selection parameters;
* PhySO symbolic-search parameters;
* reward configuration;
* learning configuration;
* free-constant optimization parameters;
* prior configuration;
* RNN cell configuration.

The `TASK`, `THRESHOLD`, and `DATA_TYPE` parameters determine which previously generated splits are used.

**Input**

The script uses:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        ├── generated_dataset/
        │   └── unit_table.csv
        └── <splits_folder_name>/
            ├── regression/
            │   ├── clean/
            │   └── noisy/
            └── classification/
                ├── thr_50/
                ├── thr_75/
                └── thr_90/
```

The selected task, threshold, and data type determine the input directory.

Each fold provides:

* `X_train_fold<i>.csv`
* `y_train_fold<i>.csv`

The unit table is loaded from the generated dataset and provides the physical units of the input variables and target.

The split configuration is loaded to determine the number of folds.

**Processing**

1. Load and validate the experiment, task, threshold, and split configuration.
2. Select the appropriate split directory according to `TASK`, `THRESHOLD`, and `DATA_TYPE`.
3. Create the corresponding results directory.
4. Select the reward configuration associated with the chosen task.
5. Build the PhySO run configuration, including learning parameters, reward settings, priors, free-constant optimization, and RNN cell parameters.
6. Save the complete PhySO configuration used for the experiment.
7. Load the physical units of the input variables and target from `unit_table.csv`.
8. For each fold:

   * load the training data;
   * prepare the input matrix and target vector;
   * reset the random seeds for reproducibility;
   * initialize PhySO;
   * run symbolic discovery for the configured number of epochs;
   * save the best discovered expression;
   * save the training log and training curves.
9. The folds are processed in parallel using the configured number of jobs.

For regression, the configured regression reward is used. For classification, the configured classification reward is used.

**Output**

For regression:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── <splits_folder_name>/
            └── results_regression/
                ├── physo_config.json
                ├── fold_0/
                │   ├── best_expression.pkl
                │   ├── training.log
                │   └── training_curves.png
                ├── fold_1/
                │   └── ...
                └── ...
```

For classification:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── <splits_folder_name>/
            └── results_classification_<threshold>/
                ├── physo_config.json
                ├── fold_0/
                │   ├── best_expression.pkl
                │   ├── training.log
                │   └── training_curves.png
                ├── fold_1/
                │   └── ...
                └── ...
```

The main output files are:

* `physo_config.json`: complete configuration used for the PhySO experiment;
* `best_expression.pkl`: best expression found for each fold;
* `training.log`: PhySO training log for each fold;
* `training_curves.png`: training curves produced during the run.

**Reproducibility**

The random seed is explicitly reset for each fold for Python's `random` module, NumPy, and PyTorch.

The same seed is therefore used when initializing each fold's PhySO run.

The generated `best_expression.pkl` files are evaluated in `05A_evaluate_best_expression.py` and the Pareto-front expressions are evaluated in `05B_evaluate_pareto_front.py`

## 5. Evaluation of the Best Expression

### `05A_evaluate_best_expression.py`

**Purpose**

The script evaluates the best symbolic expression found by PhySO for each fold.

For every fold, the saved expression is applied to both the training and test data, and the corresponding performance metrics are computed.

The evaluation procedure depends on the selected task:

* **regression**: the `SquashedNRMSE` reward is computed;
* **classification**: an optimal decision threshold is determined on the training set and then applied to both training and test predictions. The performance is evaluated using Balanced Accuracy.

**Configuration**

The script reads its parameters from:

```
configs/05_evaluate_expressions_config.json
```

The main parameters are:

* `EQ_TO_TEST`
* `EXPERIMENT_NAME`
* `SPLITS_FOLDER_NAME`
* `TASK`
* `THRESHOLD`
* `DATA_TYPE`

These parameters identify the dataset and the PhySO results to evaluate.

**Input**

The script requires the splits and PhySO results generated by the previous steps:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── <splits_folder_name>/
            ├── regression/
            │   └── <clean_or_noisy>/
            │       ├── X_train_fold<i>.csv
            │       ├── X_test_fold<i>.csv
            │       ├── y_train_fold<i>.csv
            │       └── y_test_fold<i>.csv
            └── results_<task>[_<threshold>]/
                └── fold_<i>/
                    └── best_expression.pkl
```

The number of folds is read from:

```
split_config.json
```

**Processing**

For each fold:

1. Load the training and test input data and corresponding targets.
2. Convert the data to PyTorch tensors for execution of the symbolic expression.
3. Load the `best_expression.pkl` generated by `04_run_physo.py`.
4. Execute the symbolic expression on the training and test sets to obtain predictions.

For **regression**:

1. Compute the `SquashedNRMSE` reward on the training set.
2. Compute the same reward on the test set.

For **classification**:

1. Determine the optimal decision threshold `tau_star` using only the training targets and training predictions.
2. Convert training and test predictions into binary predictions using the same `tau_star`.
3. Compute the confusion-matrix elements (`TP`, `TN`, `FP`, `FN`) separately for training and test data.
4. Compute Balanced Accuracy on both sets.
5. Save the confusion-matrix information together with the selected threshold.

The test-set threshold is therefore **not optimized independently**: the threshold determined from the training set is directly applied to the test set.

**Output**

Results are saved inside the corresponding fold directory.

For both regression and classification:

```
fold_<i>/
├── best_expression.pkl
└── rewards_best_expr.csv
```

`rewards_best_expr.csv` contains:

* `reward_train`
* `reward_test`

For classification, an additional file is generated:

```
fold_<i>/
└── confusion_matrix_best_expr.csv
```

This file contains:

* `TP_train`, `TN_train`, `FP_train`, `FN_train`;
* `TP_test`, `TN_test`, `FP_test`, `FN_test`;
* `tau_star`.

The rewards are saved with four decimal places.

### `05B_evaluate_pareto_front.py`

**Purpose**

The script evaluates the expressions belonging to the Pareto front generated by PhySO.

Instead of evaluating only the single best expression, all Pareto-front expressions are used as symbolic features. These features are then provided to the machine-learning models specified in `MODEL_LIST`.

This allows the predictive performance of the symbolic features generated by PhySO to be assessed using standard machine-learning models.

**Configuration**

The script uses the same configuration file as `05A`:

```
configs/05_evaluate_expressions_config.json
```

The main parameters are:

* `EQ_TO_TEST`
* `EXPERIMENT_NAME`
* `SPLITS_FOLDER_NAME`
* `TASK`
* `THRESHOLD`
* `DATA_TYPE`
* `MODEL_LIST`

The random seed is read from the `physo_config.json` generated by `04_run_physo.py`.

**Input**

For each fold, the script requires the training and test splits and the Pareto-front results generated by PhySO:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── <splits_folder_name>/
            ├── <task_data>/
            │   └── <clean_or_noisy>/
            │       ├── X_train_fold<i>.csv
            │       ├── X_test_fold<i>.csv
            │       ├── y_train_fold<i>.csv
            │       └── y_test_fold<i>.csv
            └── results_<task>[_<threshold>]/
                ├── physo_config.json
                └── fold_<i>/
                    ├── training_curves_pareto.csv
                    └── training_curves_pareto.pkl
```

The number of folds is obtained from `split_config.json`.

**Processing**

For each fold:

1. Load the training and test datasets.
2. Load the Pareto-front expressions from the PhySO CSV and PKL files.
3. Execute every Pareto-front expression on the training and test inputs.
4. Use the resulting expression outputs as symbolic features.
5. Remove unsafe and duplicate symbolic features.
6. Standardize the symbolic features:

   * fit `StandardScaler` on the training features;
   * transform the test features using the same scaler.
7. Save the fitted scaler.
8. For each model specified in `MODEL_LIST`:

   * initialize the model;
   * reset the random seeds;
   * fit the model on the symbolic training features;
   * generate training and test predictions;
   * save the fitted model;
   * evaluate its performance.

For **regression**, the `SquashedNRMSE` reward is computed on the training and test predictions.

For **classification**:

1. Determine the optimal decision threshold using the training predictions.
2. Apply the same threshold to the training and test predictions.
3. Compute the confusion-matrix elements for both sets.
4. Compute Balanced Accuracy.
5. Store the confusion-matrix information and the selected threshold.

The test set is therefore never used to fit the scaler, train the models, or determine the classification threshold.

**Output**

For each fold, the script generates:

```
fold_<i>/
├── StandardScaler_on_pareto_front.pkl
├── <model>_model_on_pareto_front.pkl
├── rewards_pareto_front.csv
├── confusion_matrix_pareto_front.csv
└── pareto_config.json
```

`confusion_matrix_pareto_front.csv` is generated only for classification experiments.

`rewards_pareto_front.csv` contains, for each evaluated model:

* `model`
* `reward_train`
* `reward_test`

For classification, `confusion_matrix_pareto_front.csv` contains:

* `model`;
* `TP_train`, `TN_train`, `FP_train`, `FN_train`;
* `TP_test`, `TN_test`, `FP_test`, `FN_test`;
* `tau_star`.

The fitted machine-learning models and scaler are saved as PKL files so that the evaluation can be reproduced or inspected later.

At the results-directory level, the script also saves:

```
pareto_config.json
```

which records the configuration used for the Pareto-front evaluation, including the selected models.

**Relation to `05A`**

The two evaluation scripts serve complementary purposes:

* `05A_evaluate_best_expression.py` evaluates the **single best expression** returned by PhySO directly.
* `05B_evaluate_pareto_front.py` evaluates the **entire Pareto front** by using its expressions as symbolic features for conventional machine-learning models.

The results produced by `05A` and `05B` are collected and summarized by `06_results_summary.py`

## 6. Results Summary and Statistics

### `06_results_summary.py`

**Purpose**

The script collects and summarizes the results produced by the evaluation steps.

It automatically identifies the available PhySO results for the selected experiment and data type, loads the results from all folds, associates them with the corresponding experimental configuration, and computes the final performance summaries and statistics.

No new model training or symbolic discovery is performed at this stage.

**Configuration**

The script reads its parameters from:

```
configs/06_results_summary_config.json
```

The main parameters are:

* `EQ_TO_TEST`
* `EXPERIMENT_NAME`
* `SPLITS_FOLDER_NAME`
* `DATA_TYPE`

The selected `DATA_TYPE` determines whether clean or noisy results are summarized.

**Input**

The script uses the results generated by `05A_evaluate_best_expression.py` and `05B_evaluate_pareto_front.py`.

The results are searched within:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── <splits_folder_name>/
            ├── split_config.json
            └── results_*/
                └── fold_*/
                    ├── rewards_best_expr.csv
                    ├── confusion_matrix_best_expr.csv
                    ├── rewards_pareto_front.csv
                    └── confusion_matrix_pareto_front.csv
```

The confusion-matrix files are present only for classification experiments.

The script also uses the configuration information associated with each available result to identify:

* task;
* noise condition;
* class-imbalance condition;
* classification threshold;
* data type.

**Processing**

1. Load and validate the experiment configuration.
2. Load `split_config.json` to determine the number of folds.
3. Identify all available results corresponding to the selected experiment and data type.
4. For each available result configuration:

   * load the best-expression rewards from all folds;
   * load the best-expression confusion matrices for classification;
   * load the Pareto-front rewards from all folds;
   * load the Pareto-front confusion matrices for classification;
   * associate each result with its experimental metadata.
5. Concatenate the results from the different configurations.
6. Compute the classification metrics from the confusion matrices.
7. Combine the reward and metric information into a unified results summary.
8. Compute aggregate statistics from the results summary.
9. Save both summaries as CSV files.

The actual metric computation and result aggregation are delegated to utility functions in:

```
utils/analysis_utils.py
```

**Output**

Two summary files are generated in the splits directory:

```
<splits_folder_name>/
├── results_summary.csv
└── statistics_summary.csv
```

### `results_summary.csv`

This file contains the consolidated results from the evaluated expressions and models, together with the corresponding experimental configuration.

It combines:

* best-expression rewards;
* Pareto-front model rewards;
* classification metrics derived from the confusion matrices;
* experiment metadata such as task, noise, imbalance, threshold, and data type.

### `statistics_summary.csv`

This file contains the statistical summary generated from `results_summary.csv`.

Both files are saved with four decimal places.

The summary files generated by this script are used by the visualization scripts `07A_plot_histograms.py` and `07B_plot_heatmaps.py`.

## 7. Expression Frequency Histograms

### `07A_plot_histograms.py`

**Purpose**

The script analyzes how frequently symbolic expressions occur across the different folds of the experiments.

Two separate analyses are performed:

* frequency of the **best expression** selected by PhySO;
* frequency of expressions belonging to the **Pareto front**.

The resulting frequency distributions are visualized as histograms.

**Configuration**

The script reads its parameters from:

```
configs/07A_plot_histograms_config.json
```

The main parameters are:

* `EQ_TO_TEST`
* `EXPERIMENT_NAME`
* `SPLITS_FOLDER_NAME`
* `DATA_TYPE`
* `N_DIGITS`

`N_DIGITS` controls the numerical precision used when simplifying the symbolic expressions before counting them. This allows mathematically equivalent or numerically very similar expressions to be grouped more consistently.

**Input**

The script uses the PhySO results stored in the corresponding results directories:

```text
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── <splits_folder_name>/
            └── results_<task>[_<threshold>]/
                └── fold_<i>/
                    ├── best_expression.pkl
                    └── training_curves_pareto.csv
```

The available result configurations are identified using the same result-discovery mechanism used by `06_results_summary.py`.

**Processing**

For each available result configuration:

#### Best expressions

For every fold:

1. Load the `best_expression.pkl` file.
2. Convert the expression to its SymPy infix representation.
3. Evaluate the fitted constants in the expression.
4. Simplify the numerical representation using the configured number of digits.
5. Count the occurrences of each resulting expression across folds.

#### Pareto-front expressions

For every fold:

1. Load the Pareto-front expressions from `training_curves_pareto.csv`.
2. Remove unsafe and duplicate expressions.
3. Simplify the remaining expressions using the configured number of digits.
4. Count the occurrences of each expression across folds.

The frequency counts are then passed to the plotting utility `plot_expression_frequency()`.

For classification experiments, the plot title also reports the class-imbalance level associated with the result.

**Output**

All plots are saved in:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── <splits_folder_name>/
            └── plots/
```

The generated files follow the naming convention:

```
classification_thr_<threshold>_best_expression_frequency.png
classification_thr_<threshold>_pareto_front_frequency.png
```

or, for regression:

```
regression_best_expression_frequency.png
regression_pareto_front_frequency.png
```

The plots show the frequency with which each symbolic expression appears across the folds.


### `07B_plot_heatmaps.py`

**Purpose**

The script visualizes the classification performance obtained from the results summarized by `06_results_summary.py`.

For each selected machine-learning model, it compares:

* the performance of the **best expression** found directly by PhySO;
* the performance obtained by applying the selected machine-learning model to the **Pareto-front symbolic features**.

The results are displayed as heatmaps showing the relationship between **class imbalance** and **noise level**.

**Configuration**

The script reads its parameters from:

```
configs/07B_plot_heatmaps_config.json
```

The main parameters are:

* `EQ_TO_TEST`
* `EXPERIMENT_NAMES`
* `SPLITS_FOLDER_NAMES`
* `DATA_TYPE`
* `N_DIGITS`
* `MODEL_LIST`

`EXPERIMENT_NAMES` and `SPLITS_FOLDER_NAMES` must contain the same number of elements, so that each experiment is associated with its corresponding splits directory.

`N_DIGITS` controls the number of decimal digits displayed in the heatmap annotations.

**Input**

The script uses the statistical summaries generated by `06_results_summary.py`:

```
tests/
└── <equation_name>/
    └── <experiment_name>/
        └── <splits_folder_name>/
            └── statistics_summary.csv
```

The summary must contain, among other information:

* task;
* model;
* class imbalance;
* noise level;
* mean test reward;
* standard deviation of test reward.

When multiple experiments are provided, only imbalance levels common to all selected experiments are retained.

**Processing**

For each selected experiment:

1. Load `statistics_summary.csv`.
2. Associate the summary with the experiment and splits-folder names.
3. Combine the summaries from all selected experiments.
4. Select only classification results.
5. Restrict the analysis to class-imbalance levels shared by all selected experiments.
6. Separate the results for:

   * the PhySO **best expression** (`best_expr`);
   * each model specified in `MODEL_LIST` applied to the Pareto front.
7. Construct matrices with:

   * class imbalance on the rows;
   * noise level on the columns;
   * mean test reward as the cell value.
8. Construct corresponding standard-deviation matrices.
9. Display each cell as:

```
mean ± standard deviation
```

10. Generate one figure for each selected model, with two heatmaps:

    * **PhySO (best expression)**;
    * **PhySO + model (Pareto front)**.
11. Use a common reward scale from 0 to 1.
12. Save the resulting figure as a PNG file.

The imbalance levels are displayed as percentages of positive samples.

**Output**

Plots are saved in:

```
tests/
└── <equation_name>/
    └── plots/
        ├── heatmap_best_expr_vs_<model_1>.png
        ├── heatmap_best_expr_vs_<model_2>.png
        └── ...
```

Each heatmap figure contains:

* the class-imbalance levels on the y-axis;
* the noise levels on the x-axis;
* the mean test reward in each cell;
* the corresponding standard deviation;
* a shared reward scale from 0 to 1.

The left heatmap shows the performance of the best expression found directly by PhySO, while the right heatmap shows the performance obtained by the selected model using the symbolic features extracted from the Pareto front.
